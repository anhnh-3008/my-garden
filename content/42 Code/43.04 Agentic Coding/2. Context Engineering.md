# 🌿 What?
 - Cấu trúc tốt context, tạo ra những context có thông tin chọn lọc, mạch lạc, định hướng suy luận, khả năng ghi nhớ của AI Agent

# 🌿 Why?
Nếu chỉ dựng lại ở tối promt thì vẫn còn nhiều điểm hạn chế khi bối cảnh xử lý ngày càng phức tạp lên:
- Context rot - nhiều thông tin thừa, gây nhiễu model
- Chi phi tăng cao do có token không cần thiết
- Attention budget - model dựa theo kiến trúc transformer, nôm na là model sẽ xử lý token + các token có liên kết trong context, nếu ngữ cảnh cung cấp càng dài, model sẽ bị chia mỏng sự chú ý.

# 🌿 Best Practices
- Chắt lọc
	- Tối đa hóa thông tin, tối thiểu hóa nhiễu
	- Nâng niu từng token(tui bắt chước câu nâng niu từng dòng code 🤣)
	- Coi Context Window như 1 tờ giấy, mỗi token như 1 nét vẽ trong 1 bức tranh tổng thể.
- Thiết kế Tools và Knowledge tối ưu.
- Quản lý bộ nhớ ngắn và dài hạn:
	- Ngắn hạn nên chọn lọc thông tin nào cần AI Agent ghi nhớ
	- Dài hạn ghi vào các file .md, database, để đưa lại vào Contenxt Window ở các tác vụ cần đến sau.
	- Tóm tắt nội dung thông minh.
- Định kỳ nhắc nhở mục tiêu chính & thích ứng từ sai lầm
	- Với chuỗi tương tác dài, LLM dễ quên mục tiêu ban đầu(lost in the middle)
	- Giữ lại lỗi trong ngữ cảnh => LLM cải thiện trong các suy luận tiếp theo.
- Thường xuyên review lại flow, logic
	- model luôn được update, context hiện tại chi tiết và đầy đủ cho thời điểm hiện tại nhưng ở thời điểm có model mới thì lại bị thừa.
		- vd model chatGPT5 giới hạn knowledge đến 01/10/2024, khi cần gen code với các framework sau thời điểm trên, chúng ta phải đưa vào context window doc của framework. Nhưng khi model mới được cải tiến, những thông tin trong context window sẽ không cần thiết.
